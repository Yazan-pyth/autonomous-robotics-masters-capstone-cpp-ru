# Оценивание: 25 + 15 = 40 баллов

Каждый студент получает **до 25 за свой подпроект и до 15 за интеграцию**. Пять групп не суммируют 5 × 25 в оценку одного студента. Это самостоятельная шкала проекта; пересчёт в общую оценку курса преподаватель объявляет отдельно.

## Подпроект — 25

| Критерий | Максимум | Полный балл |
|---|---:|---|
| Постановка, математика, интерфейсы | 3 | Чёткая гипотеза, модели/ограничения, корректные contracts и связь с курсом |
| Классический метод | 5 | Рабочий C++ baseline, содержательный собственный вклад, correctness/edge-case tests |
| DL/RL-метод | 5 | Обучение/дообучение, clean split, reproducible artifact, C++ inference и fallback |
| Эксперименты и анализ | 6 | Fair comparison, полный объём seeds, метрики/CI, ablation, cost и failure analysis |
| Код, Git, Docker | 3 | Сборка из clean clone, tests/review, manifest, контейнер и воспроизведение |
| Отчёт и индивидуальная защита | 3 | До 1 балла за общий отчёт; до 2 за личное объяснение обоих методов и своего вклада |
| **Итого** | **25** | |

За частичное выполнение каждого критерия: 0 — нет доказательств; около 50% — частично работает/существенные пробелы; около 75% — работает, есть отдельные недостатки; 100% — требования подтверждены. Разрешены шаги 0.5 балла. Оценка ниже — с конкретными ссылками на missing evidence, а не на размер команды.

Если один метод отсутствует, соответствующие 5 баллов равны нулю, а строка «Эксперименты и анализ» ограничена 2/6, поскольку сравнение не проведено. При отсутствии learned artifact/обучения heuristic не засчитывается как DL/RL. Если runtime алгоритм реализован только на Python, баллы за соответствующий C++ метод не начисляются до исправления. Offline training на Python разрешён.

Test leakage делает затронутые экспериментальные результаты недействительными: их необходимо повторить; за неповторённые результаты баллы за сравнение не начисляются. Отрицательный результат или проигрыш DL/RL не снижает оценку сам по себе.

## Интеграция — 15

| Критерий | Максимум | Доказательство |
|---|---:|---|
| Пять компонентов и общая миссия | 4 | 4/4: C0 и C6 проходят end-to-end, у всех групп active runtime role; 2/4: одна полная конфигурация; 1/4: только частичная цепочка; 0: отдельные demo |
| Запуск и контракты | 3 | 1: clean Docker launch; 1: TF/time/QoS/action correctness; 1: reset/readiness и повторный запуск |
| Системное сравнение и отчёт | 3 | 1: C0…C6 и обязательные сценарии; 1: aggregates/CI/raw logs; 1: объяснение interactions и ограничений |
| Безопасность и recovery | 2 | 1: единый monitor и driver watchdog; 1: воспроизводимые fault tests и анализ |
| Индивидуальная интеграционная работа | 3 | По 1: реализованный cross-group contract/test; review/исправление интеграционного дефекта; личная демонстрация диагностики |
| **Итого** | **15** | |

Первые 12 интеграционных баллов общие для всей команды, последние 3 — индивидуальные. Smoke `/clock` из starter не даёт баллов за готовую интеграцию пяти подсистем. Отсутствующий компонент означает неполную цепочку, даже если видео показывает движение stock Nav2.

## Прозрачная индивидуальная оценка

Для подпроекта первые 22 балла + 1 балл общего отчёта являются оценкой результата группы. Оставшиеся 2 — личная защита. Итог студента:

`S_group(0..23) + S_defence(0..2) + I_system(0..12) + I_individual(0..3)`.

Каждый ведёт [CONTRIBUTION.md](../templates/CONTRIBUTION.md): issue/PR, review, тест, эксперимент, документ/раздел. Количество commits/строк не является метрикой вклада. Peer review помогает проверить факты, но не создаёт скрытых множителей. При споре преподаватель использует конкретные артефакты и индивидуальную защиту; правила не меняются после сдачи.

## Чек-лист финальной сдачи

- Release tag и commit SHA, clean build, Docker instructions.
- Два метода каждой группы и model hashes; все тесты и CI status.
- 5 group reports + 1 integration report, raw CSV/aggregates/plots.
- Scenario/model/dataset manifests и воспроизводимые команды.
- Demo C0/C6, fault demonstration, logs по семи конфигурациям.
- 12 contribution records, защита обоих методов каждым студентом.

Студенты не получают дополнительные баллы за GPU, дорогую модель или реального робота вместо полноты минимального задания.
