# Постановка магистерского проекта

Сокращения раскрыты при первом употреблении; [полный словарь терминов](GLOSSARY.md).

## Исследовательский вопрос

При одинаковых наблюдениях, ограничениях робота и вычислительном бюджете, какие обучаемые компоненты улучшают доставку в изменяющейся среде? Как локальное улучшение влияет на всю систему? Победа DL (Deep Learning — глубокое обучение)/RL (Reinforcement Learning — обучение с подкреплением) не является требованием: корректный отрицательный результат оценивается наравне с положительным.

## Мир и миссия

Один дифференциальный робот работает на плоском складе примерно 20 × 20 м: 4–6 станций, проходы, статические стеллажи и движущиеся препятствия. Радиус робота 0.25 м, дополнительный номинальный запас 0.10 м; скорость вперёд 0–0.6 м/с, угловая скорость ±1.2 рад/с. Ограничения ускорения: 0.5 м/с² и 1.5 рад/с². Это стартовые проектные требования, а не измеренные характеристики оборудования. Группа фиксирует их в неделю 2 и не меняет между методами.

Датчики: wheel odometry и IMU (Inertial Measurement Unit — инерциальный измерительный модуль) 50 Гц, 2D (Two-Dimensional — двумерный) LiDAR (Light Detection and Ranging — измерение расстояний с помощью света; лазерный дальномер) 10 Гц, RGB-D (Red, Green, Blue and Depth — цветное изображение и карта глубины) и CameraInfo 10 Гц. RGB-D достаточно для G2; LiDAR используется G1 и независимым safety monitor. Точные шумы, FOV (Field of View — поле зрения датчика), разрешение и задержки заносятся в manifest. Скриптовые движущиеся препятствия подчиняются одинаковому seed, но при взаимодействии с роботом траектории методов могут расходиться — это фиксируется как ограничение paired evaluation.

Миссия длится 300 секунд simulation time; заявки поступают по заранее заданному расписанию, каждая содержит pickup, dropoff, release time и due time. Вместимость — одна заявка. Обслуживание станции: 2 с при расстоянии ≤0.25 м и скорости ≤0.05 м/с. Доставка считается выполненной только после последовательных pickup и dropoff. При collision эпизод прекращается, завершённые до столкновения заявки сохраняются в журнале. При deadlock/timeout эпизод также не удаляется из результатов.

Для основной finite-workload серии использовать 6 заявок с release times `[0, 20, 50, 80, 120, 160]` с, due time `release + 120` с; пары станций генерируются по scenario seed. Заявки должны быть индивидуально достижимы на nominal static map; невозможность выполнить всю очередь из-за congestion остаётся результатом эксперимента. Можно изменить этот общий workload на validation до freeze недели 2, сохранив schedule и правила одинаковыми для всех конфигураций. Например, если nominal baseline физически не успевает обслужить станции даже без помех, уменьшить workload до фиксации test.

## Что входит в минимальный объём

- Однократное построение геометрической карты классическим SLAM (Simultaneous Localization and Mapping — одновременная локализация и построение карты) в mapping-phase. Для сравнений всех методов используется один зафиксированный map artifact. Оценка карты и pose graph относится к G1, но SLAM не нужно заново писать с нуля.
- Онлайн-локализация G1, obstacle/traversability map G2, глобальный путь G3, локальный контроллер G4 и очередь заявок G5.
- Переключаемые `classical` / `learned` реализации и их runtime fallback.
- Сборка, unit/contract/integration tests, replay, логирование и измерение latency на CPU (Central Processing Unit — центральный процессор). GPU (Graphics Processing Unit — графический процессор) допустим с отдельной таблицей.
- Демо интеграции и экспериментальные сравнения по общему протоколу.

Стартовая локализация известна с одинаковым ограниченным шумом. Полная глобальная релокализация, multi-floor, манипулятор, MARL (Multi-Agent Reinforcement Learning — многоагентное обучение с подкреплением) и sim-to-real — расширения после выполнения минимума. Карта тестового мира может быть получена отдельным mapping-pass; его данные не разрешается использовать для обучения моделей. Одна и та же карта выдаётся обоим сравниваемым методам.

## Связь с исходным курсом

| Модули курса | Практическое применение |
|---|---|
| 1: systems/benchmarking | manifest, reproducibility, profiler, общий runner |
| 2–4: SE(2) (Special Euclidean Group in Two Dimensions — группа перемещений и поворотов твёрдого тела на плоскости), estimation, SLAM | G1, sensor model, EKF (Extended Kalman Filter — расширенный фильтр Калмана), ICP (Iterative Closest Point — итеративный алгоритм ближайших точек для совмещения облаков точек), TF (Transform library — библиотека преобразований между системами координат) и карта |
| 5: world models | G1/G2, occupancy, traversability, unknown space |
| 6: path planning | G3, A* (A-star — алгоритм поиска пути с оценкой уже пройденной стоимости и эвристикой оставшегося пути), collision checking, replanning |
| 7–8: MPC (Model Predictive Control — управление с прогнозирующей моделью)/tracking | G4, ограничения и tracking error |
| 9: Nav2 (Navigation 2 — стек навигации для второй версии платформы Robot Operating System)/BT (Behavior Tree — дерево поведения) | G3–G5, lifecycle, action feedback/cancel |
| 10–11: ML (Machine Learning — машинное обучение)/DL | G1–G3, split, inference, calibration, OOD (Out of Distribution — данные или условия вне обучающего распределения) |
| 12: RL | G4 PPO (Proximal Policy Optimization — алгоритм оптимизации политики с ограничением величины её обновления) и G5 DQN (Deep Q-Network — глубокая нейронная сеть для оценки ценности действий), reward versus task metrics |
| 13: safety | независимый monitor, fault injection и fallback |
| 14: multi-agent bridge | интерфейсы для будущего расширения; MARL не требуется |

Существующие библиотеки разрешены: Eigen, OpenCV (Open Source Computer Vision Library — открытая библиотека компьютерного зрения), PCL (Point Cloud Library — библиотека обработки облаков точек), solver для MPC, SLAM Toolbox, Nav2, BehaviorTree.CPP, ONNX (Open Neural Network Exchange — открытый формат обмена моделями нейронных сетей) Runtime/LibTorch. Каждая подгруппа документирует, что реализовала самостоятельно: модель и fusion G1, обработку G2, стоимость/поиск G3, формулировку MPC и RL G4, политику диспетчеризации G5. Запуск готового demo без собственного алгоритмического вклада не закрывает метод.

## Почему распределение 3 + 2 + 2 + 3 + 2

G1 получает третьего студента для симулятора, датчиков и геометрии. G4 — для независимого safety monitor и fault suite. G5 координирует сборку, но не реализует чужие компоненты: каждая группа поставляет свой адаптер, тесты, Docker-зависимости и участвует в интеграции. Роли и review описаны в [WORKFLOW.md](WORKFLOW.md).
